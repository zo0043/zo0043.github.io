{{- /* 元数据防泄漏闸门（全站只跑一次，由 wiki-index.html 调用）。 背景：双链只在 layouts 里渲染（正文经 wikilinks.html 处理）， 而 meta description / og / twitter / RSS 这几处直接取 .Description 或回退 .Summary， 完全绕过管线。于是会出现两种问题： (a) 正文含「真的会被渲染成链接」的 [[…]] 却没有 description → 回退 .Summary → 字面 [[…]] 泄漏到上述四处（作者看不见，所以用 errorf 硬失败）； (b) description 自身含 [[…]] → 原样进入 meta/og/twitter/RSS（写在源文件里、看得见，故只 warnf 提醒）。 判定「真的会被渲染成链接」必须与渲染层同口径：剔除围栏代码、行内代码、 以及反斜杠转义写法（\\[[…]]）。否则一篇“讲解双链语法”的文章里， 代码块中的示例就会把构建打红——那是误报。 约定见 content/wiki/双链语法.md。 */ -}} {{- range site.Pages -}} {{- $body := replaceRE "(?s)```.*?```|~~~.*?~~~" "" .RawContent -}} {{- $body = replaceRE "`[^`]*`" "" $body -}} {{- /* 2 个以上反斜杠才是转义；单层 \[ 会被 markdown 吃掉、最终仍渲染成真链接 */ -}} {{- $body = replaceRE `\\{2,}\[\[[^\]]+\]\]` "" $body -}} {{- $hasLink := findRE `\[\[[^\]]+\]\]` $body -}} {{- $desc := trim (.Description | default "") " " -}} {{- if and $hasLink (eq $desc "") -}} {{- errorf "双链元数据：%s 正文含未转义的 [[…]] 但没有 description。og/twitter/meta/RSS 会回退到 .Summary，把字面 [[…]] 泄漏出去——请补一个 description（纯散文，不要含 [[…]]）。" .RelPermalink -}} {{- end -}} {{- if findRE `\[\[[^\]]+\]\]` $desc -}} {{- warnf "双链元数据：%s 的 description 含 [[…]]。该字段会原样进入 meta/og/twitter/RSS，不会被渲染成链接；建议改成散文。" .RelPermalink -}} {{- end -}} {{- end -}} {{- return true -}}
